# Barcode & QR Billing, Hardware Guns, and Item Identification

## 1. Symbologies & Data Architecture

### 1.1. Generation Standards
- **1D Barcode**: **Code 128 (Auto Subsets A/B/C)**
  - Web: Vector SVG via `JsBarcode`.
  - Backend: Vector drawing via `reportlab.graphics.barcode.code128.Code128`.
  - Fallback hierarchy if barcode is unassigned: `item.barcode || item.sku || item.publicItemId || 'ITM-1001'`.
- **2D Barcode**: **QR Code (ISO/IEC 18004, Model 2)** with ECC Level M (~15%)
  - Web: Canvas/DataURL via `qrcode`.
  - Backend: Vector widget via `reportlab.graphics.barcode.qr.QrCodeWidget`.
  - Standard payload: `ITEM:<publicItemId>`.

### 1.2. Scanning Mechanisms
- **Camera Video Stream (`html5-qrcode`)**:
  - Decodes Code 128, Code 39, Code 93, EAN-13, EAN-8, UPC-A, UPC-E, ITF, Codabar, QR Code, Data Matrix, Aztec, PDF417.
  - Requires 750ms frame throttle to prevent runaway duplicate counting on continuous video feeds.
  - Use `useRef` for standby flags (`isStandbyRef.current`) to prevent stale closures from prematurely closing scanner modals.
- **Hardware Scanner Guns (USB / 2.4G / Bluetooth)**:
  - Acts as an **HID Keyboard Wedge** emitting rapid keystrokes (<35ms per character) followed by `Enter`.
  - Intercepted globally via `useBarcodeScanner` hook.
  - Zero debounce cooldown (`isHardwareTrigger = true`) so consecutive physical trigger pulls immediately increment item quantity.
  - Must call `e.preventDefault()` on `Enter` if an input field is focused to prevent unintended form or modal submissions.
  - Accepts **ANY barcode symbology** decoded by the gun firmware (including GS1-128, ISBN, and industrial codes).

### 1.3. Multi-Attribute Item Matching (`isSameItem`)
When adding to cart or verifying inventory, never rely on a single attribute like `c.item.id === item.id`. Match across all valid identifiers:
```typescript
export function isSameItem(a?: Item | null, b?: Item | null): boolean {
  if (!a || !b) return false;
  if (a.id && b.id && a.id === b.id) return true;
  if ((a as any)._id && (b as any)._id && (a as any)._id === (b as any)._id) return true;
  if (a.id && (b as any)._id && a.id === (b as any)._id) return true;
  if ((a as any)._id && b.id && (a as any)._id === b.id) return true;
  if (a.publicItemId && b.publicItemId && a.publicItemId.trim().toLowerCase() === b.publicItemId.trim().toLowerCase()) return true;
  if (a.barcode && b.barcode && a.barcode.trim().toLowerCase() === b.barcode.trim().toLowerCase()) return true;
  if (a.sku && b.sku && a.sku.trim().toLowerCase() === b.sku.trim().toLowerCase()) return true;
  return false;
}
```

### 1.4. POS Cart Persistence Rule
- Active POS cart state MUST be synchronized with `localStorage` (`qb_pos_cart`).
- Restored automatically on page refresh (`F5`) or tab re-opening.
- Cleared only upon explicit checkout completion, "Discard Sale", or branch switching.
- Guard location polling intervals on component mount to prevent wiping restored items during initial hydration.

## 2. Core Principles & Payload Specifications

### 2.1. Safe Payload Structure
All item QR codes generated by the application MUST adhere strictly to the prefix format:
```text
ITEM:<publicItemId>
```
*Example:* `ITEM:itm_9f8a7b6c5d4e`

### 2.2. Security Rules (What NOT to encode)
- **NEVER** encode raw MongoDB internal `_id` (`ObjectId`).
- **NEVER** encode prices, discounts, tax rates, or item names in the QR payload (these are mutable and must be fetched authoritatively from the server).
- **NEVER** encode user authentication tokens, API keys, or sensitive customer PII.
- **Cross-Tenant Protection**: The API lookup endpoint `/items/lookup/qr/{publicItemId}` MUST verify that the resolved item belongs to the authenticated user's current `businessId`. If the QR code belongs to a different business, return a `404 Not Found` without disclosing any details.

## 3. Label Dimensions & Layout
Standard barcode/label sticker formats supported:
1. **Thermal 50x30mm**:
   - Store Name (Header, 7pt bold)
   - Item Display Name (truncated if > 26 chars, 8pt bold)
   - Centered 1D Barcode (Code 128, 10mm high) or 2D QR Code (14mm x 14mm)
   - Human-readable code text (SKU / Barcode, 7pt mono)
   - MRP & Sale Price (e.g., `₹ 150.00`, 9pt bold)
2. **Jewelry Dumbbell Tag (70x12mm)**: Dual-flap layout with micro QR / Barcode on one flap, item details and net weight on second flap.
3. **A4 Sticker Sheet (24 / 40 labels per page)**: Standard grid for desktop laser/inkjet label sheets.

## 4. Backend Item Lookup Implementation (FastAPI)

```python
from fastapi import APIRouter, Depends, HTTPException, status
from app.core.security import get_current_business_id
from app.repositories.item_repository import ItemRepository
from app.schemas.item import ItemResponse

router = APIRouter(prefix="/items", tags=["Items"])

@router.get("/lookup/qr/{public_item_id}", response_model=ItemResponse)
async def lookup_item_by_qr(
    public_item_id: str,
    business_id: str = Depends(get_current_business_id),
    item_repo: ItemRepository = Depends(),
):
    item = await item_repo.find_by_public_id(business_id=business_id, public_item_id=public_item_id)
    if not item:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="Item not found in current business catalog."
        )
    if not item.is_active:
        raise HTTPException(
            status_code=status.HTTP_400_BAD_REQUEST,
            detail="This item is marked inactive and cannot be billed."
        )
    return item
```

## 5. Verification Checklist
- [ ] Product QR codes decode to `ITEM:<publicItemId>` format.
- [ ] 1D barcodes encode clean alphanumeric strings via Code 128.
- [ ] Scanning QR from a different tenant returns 404 without leaking item names.
- [ ] Re-scanning an already-added item increases quantity without adding a duplicate row.
- [ ] Hardware gun keystroke triggers bypass repeat debounce and increment count immediately.
- [ ] Cart items survive browser refresh (`F5`).
- [ ] Label PDF renders clearly on standard thermal/sticker printers.
